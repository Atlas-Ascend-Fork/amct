## 4 重点用例说明

### TC-004 / TC-005：入口组合边界

目的：证明 pipeline 由 config 决定，且错误组合在重资源操作前失败。操作：分别传 nn.Module + layerwise 和 str + full。预期：前者抛 TypeError，后者显式说明未实现。实际：与预期一致。

### TC-013：样本数关系

目的：证明 batch_num、batch_size、num_calibration_samples 不允许矛盾。操作：参数化覆盖只给一个、给两个、给三个的情况。预期：规范化后满足 nsamples = batch_num × batch_size，矛盾即 ValueError。实际：全部通过。

### TC-024 / TC-025：缓存复用与重抽

目的：证明缓存只有完整且身份匹配才可复用。操作：先完整 PTQ 一次；再篡改 block_0_mlp_in.pkl 后换新 result dir 重跑。预期：第一次复用不增加 Extract 调用；篡改后重新 Extract。实际：均通过。

### TC-029：真实 Linear 输入

目的：证明 down_proj 不误用 MLP 输入。操作：对三个真实 Linear 挂 forward hook，再执行 QuantGatedMLP 语义 forward。预期：gate/up 输入相同，down 输入为激活后 hidden。实际：三个输入均捕获成功。

### TC-036：失败不发布

目的：证明 PTQ 中断不会生成可加载 artifact。操作：让第二层 build_quant_block 抛 RuntimeError。预期：目录无 quant_manifest.json。实际：断言通过。

### TC-038 / TC-041：真实模型规模

Qwen3-0.6B 有 28 层 FFN，每层 gate/up/down 三个 Linear，因此 weight-only 与静态 MinMax 都是 84 个 unit。静态路径另有 28 个 block 激活文件。

### TC-045 / TC-046 / TC-047：Classic full 对照

这组不是 layerwise 功能测试，而是防止里程碑 2 破坏里程碑 1 的协议回归。MinMax 和 GPTQ reload 后 forward bit exact；AWQ reload 后 max_abs_diff 为 0.005859375，符合 Week 3/4 对 AWQ 允许一个舍入步差异的合同。

## 9 缺陷记录与修复

测试过程中发现并修复的问题：

| 问题 | 影响 | 修复 |
|------|------|------|
| 期望算法集合未包含 minmax | 算法注册测试失败 | 更新测试期望集合 |
| Qwen adapter QuantLinear 包装导致无法找到真实 Linear | unit plan 失败 | 支持 .linear 解析 |
| bfloat16 权重与 float 输入 dtype 不匹配 | forward 报错 | 捕获输入后按权重 dtype 转换 |
| stream config fingerprint 与 full model 指纹序列化不一致 | reload 指纹校验失败 | 统一 canonical JSON/tensor 字节摘要规则 |
| static MinMax hook 逻辑不适配 QuantGatedMLP | down 输入或捕获错误 | 按真实 gated MLP 语义 forward 并挂真实 Linear hook |

当前无已知未修复的 layerwise P0 缺陷。

## 10 检视结论

- 需求 FR-001 至 FR-016 均有自动化或真实模型证据。
- Week 5-8 的代码路径均有负向测试，不只测 happy path。
- full 旧路径和 V2 协议有回归保护。
- 测试报告没有把 Classic full 的 AWQ/GPTQ 通过结果说成 layerwise 支持。
- NPU 和 benchmark 的未执行边界已单独列出，不伪装成通过。
