# 量化方案推荐

## 用户调用格式

- 如果用户明确点名调用这个 skill，先返回这个 skill 对应的固定输入模板，再开始执行。
- 不替用户改成别的 skill；只有当用户没有指定 skill、只是描述目标时，才建议是否回到 `$quant-workflow`。
- 固定输入模板见：[../../reference/skill-input-template.md](../../reference/skill-input-template.md)

这个 skill 只用于**推荐第一轮量化方案**。

它回答的问题是：

- 第一枪先量哪些模块
- 用什么 `dtype / bits / algos / granularity`
- 为什么先从这个方案起步
- 如果失败，先缩哪里、查哪里

它不负责：

- 真正跑量化实验
- 产出 `ppl_bf16 / ppl_quant / delta`
- 做误差定位
- 下“最终最优方案”结论

按下面顺序阅读：

1. `.agents/docs/casebook/...` 中对应系列的 `README.md`
2. 如已有个案，再读最相近的 `<series>/<case>.md`
3. 如需确认当前能力边界，再读 [../../../docs/repo-map.md](../../../docs/repo-map.md)
4. 如需确认当前量化口径，再读 [../../quant-workflow/references/metrics-and-thresholds.md](../../quant-workflow/references/metrics-and-thresholds.md)

## 固定流程

1. 先明确当前任务口径：
   - 模型名称 / 系列
   - 结构标签：`dense / moe / packed-expert / special-attn`
   - 评测集、指标、`seq_len`、`granularity`
   - 时间预算、算力预算、是否优先保守
2. 先查现有结果：
   - 系列 `casebook` 是否已有默认起步方案
   - `outputs/` 或日志里是否已有相同口径的量化结果
   - 当前模型和历史案例是否足够相似
3. 按相似度筛选参考经验，优先级是：
   - 同系列
   - 同结构
   - 同量化目标
   - 同评测口径
4. 至少给出 2 到 3 个候选方案：
   - 保守方案
   - 默认首推方案
   - 激进覆盖方案
5. 从候选中选一个“首推方案”，并明确理由：
   - 证据最强
   - 成本最低
   - 失败后最容易定位
6. 用最终保留模块填写风险点、升级条件和回退路径。
7. 输出“量化方案推荐卡”，卡片内容以最终保留方案为准。

## 边界规则

- 这是**起步方案推荐**，不是全仓最优方案搜索。
- 不要按全仓平均经验直接推荐，要优先参考同系列、同结构案例。
- 如果评估依据不足，要明确写“弱推荐”或“待验证”，不要装作确定。
- 如果用户已经明确给了量化方案，停止推荐，转到评测或验证流程。
- 如果模型还没适配完成，停止推荐，回到 `$model-adapter`。
- 如果当前仓库里已有同口径、同模型、同目标的稳定结论，优先复用，不重复发明方案。
- 当前推荐卡主字段按模块级表达，不强制做子算子级拆分。
- 除非有稳定 casebook 佐证，不要把结构经验写成“已验证结论”。
- 引用仓库内代码、脚本和文档路径时，一律使用仓库相对路径；不要写绝对路径。

## 输出要求

结束时必须给出一张“量化方案推荐卡”，至少包含下面字段：

- `当前模型`
- `任务口径`
- `相似案例`
- `候选方案`
- `首推方案`
- `推荐理由`
- `风险点`
- `升级条件`
- `回退方案`
- `证据强度`
