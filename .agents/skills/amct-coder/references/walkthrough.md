# 走查示范

本文件是 [SKILL.md](../SKILL.md) 各规则的协作形态示范，演示一次正常的**停止扩张并开始交付**长什么样：扩张在什么信号下停止、证据如何分级、交付如何落笔。

## 加载时机

- 首次进入本 skill 且任务为诊断、review 或规划（不落盘代码）时读取——走查场景即为诊断类，帮助对齐停止扩张与交付行为。
- 编码任务不默认读取；发现自己在「读了很多资料仍未收敛」时读取一次，对照第 5～6 步校准。
- 同一会话第二次起不再读取。

## 走查

请求：「PTQ 训练日志显示参数更新，但 eval PPL 没有变化」。

```text
1. 职责归属：行为诊断、不改代码，属本 skill；不转执行/判读类 skill。
   （PPL 数字本身的达标判读才转 reviewer skill；此处只查状态为什么没传导。）
2. 主手册：llm-solving-lifecycle。按「必读公共节 + 命中场景节」读取：
   公共节（职责边界/禁止项）+「参数回载诊断」节；不预读 deploy/algorithm
   手册，也不读 granularity 门禁等未命中场景节。
3. 锚点（首轮 3 个）：
   - 训练保存链：LlmPtqWorkflow._save_unit_result 的 caller 链
   - 回载侧：eval 的参数加载入口与 strict 行为
   - 直接测试：test_ptq_params.py 中 export_unit/load_unit 断言
4. 核对快照：执行手册中「主链状态」附带的核对命令（如 export_unit 无非测试
   caller 的反向 grep），确认快照未过期。
5. 证据分级并收口：
   - 源码存在：PtqParamHandler.export_unit 定义 ✓
   - 单测覆盖：helper 直接断言 ✓
   - 集成闭环：训练保存链不经过该 helper —— 只到「源码存在」级
   → 该发现只能排除「helper 链保存了参数」这一种可能，不能回答
     「保存的到底是什么」；回答症状本身还差两步：
     a. 实际算法状态是否进结果：沿 finalize 的 fallback 语义核对
        trainable 参数（clip_factor 等）是否真实出现在保存的 key 里；
     b. 保存内容是否被 eval 消费：加载入口的默认目录、strict 行为、
        缺失时的日志级别。
   → 两步各取一个锚点。停止扩张的边界：停止读**无关**资料（deploy 手册——
     症状与 deploy 无关；全部测试文件枚举——已能区分日志信号与保存内容）；
     **相关调用链仍可查时继续查**，与主流程「证据仍缺就继续读」一致。
     只有遇到具体阻塞（需 NPU/权重的运行时证据、用户命令行信息、需授权的
     实验）才停止，按初步排查交付并写明阻塞点。
6. 交付（没改代码形态）：分析边界、已闭环事实（保存链走 solver.finalize
   结果 + torch.save，helper 未接通）、按 a/b 核对后确认或排除的事实、
   仍待确认项（须为已明确的具体阻塞，不是「还可以再查」）、建议验证
   （mocked workflow 回载断言）。不写「已验证」，因为只有源码级证据。
```

## 反例

即被 process-rules「读取预算与停止条件」各禁止规则覆盖的行为：为「证明无关」而通读 deploy 手册、把 helper 单测通过写成集成闭环、把「排除了一个候选」当「找到了根因」后提前交付、替用户猜 strict 语义。

若当前任务与本走查场景不同，仿照的是步骤形态（归属→手册→锚点→核对→停止扩张→按所走路径交付），不是其中的具体符号。
