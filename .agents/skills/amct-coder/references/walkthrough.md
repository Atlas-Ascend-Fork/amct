# 完整示范

本文件是一次完整任务的示范，演示**停止查资料并开始交付**长什么样：查资料在什么信号下停止、证据如何分级、交付如何落笔。

## 示范

请求：「PTQ 训练日志显示参数更新，但 eval PPL 没有变化」。

```text
1. 定动作：行为诊断、不改代码（查的是状态为什么没传导，
   不是 PPL 数字达不达标。）
2. 主场景手册：llm-solving-lifecycle。每次都读职责边界、禁止项，
   命中才读「参数回载诊断」；不预读 deploy/algorithm 手册，
   也不读 granularity 前置检查等未命中节。
3. 锚点（首轮 3 个）：
   - 训练保存链：LlmPtqWorkflow._save_unit_result 的 caller 链
   - 回载侧：eval 的参数加载入口与 strict 行为
   - 直接测试：test_ptq_params.py 中 export_unit/load_unit 断言
4. 核对「当前事实」：执行手册中该节附带的核对命令（如 export_unit 无非测试
   caller 的反向 grep），确认断言未过期。
5. 证据分级并收口：
   - 源码存在：PtqParamHandler.export_unit 定义 ✓
   - 单测覆盖：helper 直接断言 ✓
   - 集成闭环：训练保存链不经过该 helper —— 只到「源码存在」级
   → 该发现只能排除「helper 链保存了参数」这一种可能，不能回答
     「保存的到底是什么」；回答症状本身还差两步：
     a. 实际算法状态是否进结果：沿 finalize 的 fallback 语义核对
        trainable 参数（clip_factor 等）是否真实出现在保存的 key 里；
     b. 保存内容是否被 eval 消费：加载入口的默认目录、strict 行为、
        缺失时的日志级别。
   → 两步各取一个锚点。停止查资料的边界：停止读**无关**资料（deploy 手册——
     症状与 deploy 无关；全部测试文件枚举——已能区分日志信号与保存内容）；
     **相关调用链仍可查时继续查**，与主流程「证据仍缺就继续读」一致。
     只有遇到具体阻塞（需 NPU/权重的运行时证据、用户命令行信息、需授权的
     实验）才停止，按初步排查交付并写明阻塞点。
6. 交付（没改代码形态）：开头一句报链路，不报文件名清单——「已核对训练
   保存链与 eval 回载入口；保存内容是否真被 eval 消费这一环没验到，需实跑
   一轮」。接着写分析边界、已闭环事实（保存链走 solver.finalize 结果 +
   torch.save，helper 未接通）、按 a/b 核对后确认或排除的事实、仍待确认项
   （须为已明确的具体阻塞，不是「还可以再查」）、建议验证（mocked workflow
   回载断言）。不写「已验证」，因为只有源码级证据。
```

## 反例

即违反停止查资料条件的行为：为「证明无关」而通读 deploy 手册、把 helper 单测通过写成集成闭环、把「排除了一个候选」当「找到了根因」后提前交付、替用户猜 strict 语义。

若当前任务与本示范场景不同，仿照的是步骤形态（定动作→选主场景手册→锚点→核对→停止查资料→按所走路径交付），不是其中的具体符号。
