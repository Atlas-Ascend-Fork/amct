# 术语表：glossary

本文件是本 skill 自造词的唯一出处。各 reference 与 [SKILL.md](../SKILL.md) 直接使用这些词、不再解释；遇到不明术语回这里查。本表是查阅资料，按需查单行、不整读。

**收词准入（三条全中才留，否则写白话）**：

1. **消歧**：不命名就会产生歧义。白话只是更长、并不更含糊时，直接写白话。
2. **跨文件句柄**：≥3 个文件引用同一概念。单文件词汇就地展开即可。
3. **不撞领域词**：与本仓领域词、代码符号**不同形也不近形**，含近形字与同形异义。已踩过的坑：「敏感层」是本仓产品术语量化敏感层（`README.md`「回退敏感层」、`ROADMAP_2026Q4.md`「LLM 量化敏感度分析」在建能力）；「契约状态模型」的「模型」在本仓指神经网络模型（`模型` 1448 处 / `model` 12614 处）；「收束」与领域侧「收敛」近形且同仓并存。

领域词与代码符号（`PtqUnit`、granularity、`export_deploy`、bit policy 等）一律不收，以源码为准——它们直接指向源码，抄进术语表只会造出第二份会腐化的真相。

| 术语 | 含义 |
| --- | --- |
| 主手册 | 本次任务唯一的主场景 reference（SKILL.md「场景 Reference 导航」的「主场景」行）。一个任务只选一个，第二个只能作辅助；豁免情形见 SKILL.md 首段直达卡。 |
| 门禁对象 | 命中即强制升重级的对象：新 dtype / 新算法 / 新 solver / 新 granularity、复合 unit、skip/partial result。共同点是「注册成功不等于可用」。 |
| 契约状态表 | 重级任务逐项填写的表，把「当前仓库事实」与「目标契约」分账，未冻结项标 `pending`。填法受 [process-rules「重级的比例原则」](process-rules.md#追加判据与各级流程) 约束；实体表见 [quant-dtype-module「契约状态表」](quant-dtype-module.md#契约状态表)。 |
| 快照 / 核对命令 | 手册里对当前源码状态的断言，附一条可执行的 `rg`/`grep` 命令；不是测试里的张量快照（`x.clone()`）。冲突时以命令结果为准，不以文档为准；引用快照事实作落点依据前先跑它。 |
| 事实纪律 Q1/Q2/Q3 | 待核实契约的消歧顺序：源码能查就查（Q1）→ 不影响公开契约的局部选择自行决定（Q2）→ 查不到且不同答案产出不兼容实现才问用户（Q3）。第一个「是」即停。规则正文以 SKILL.md「各级都要做」为唯一出处。 |
| BLOCKER | 手册中标注的硬约束。语义是「这个方案错了」，不是「任务停止」：替代路径明确且在用户目标内就直接继续。全局清单以 [process-rules「全局 BLOCKER」](process-rules.md#全局-blocker) 为唯一出处，轻级可违反的三条内联在 SKILL.md「各级都要做」。 |
