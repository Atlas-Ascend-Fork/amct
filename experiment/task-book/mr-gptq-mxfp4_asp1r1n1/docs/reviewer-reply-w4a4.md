## W4A4 精度评估 —— 已达标，附优化路径与 35B 口径请示

按评审要求（用 W4A4 评估最终效果、精度劣化 ≤0.4、量化层占比按层数算 ≥70%），
Qwen3-8B 的 W4A4 配置**已达标**，汇报如下。

### 一、结论

Qwen3-8B，WikiText2，seq_len=4096，**全量 73 块**，bf16 基准 PPL = 8.9893：

| 指标 | 实测 | 门槛 | 判定 |
|---|---|---|---|
| **精度劣化 delta** | **0.3897**（PPL 9.3790） | ≤ 0.40 | ✅ |
| **真 4-bit 激活层占比** | **180 / 252 = 71.4%** | ≥ 70% | ✅ |
| 权重量化层占比 | 252 / 253 = 99.6%（仅跳过 lm_head） | ≥ 70% | ✅ |
| 显存降低 | 62.3%（全模型）/ 67.4%（Linear 权重） | ≥ 50% | ✅ |

W4A4 delta 从初始实现的 **0.763 优化至 0.3897，降低 49%**。
主线 W4A16 结论不变，仍为推荐生产配置（8B delta 0.273 / 35B delta 0.067）。

复现命令：

```bash
python run_eval.py --model_path <Qwen3-8B> --mode mr_gptq \
    --seq_len 4096 --hadamard_k 4096 --hadamard_full --perc_damp 0.2 \
    --act_protect down_proj o_proj \
    --increments hadamard scale_fitting act_quant act_scale_fit joint_comp
```

### 二、混合精度的口径披露

对 `o_proj`（输入 = 注意力输出）与 `down_proj`（输入 = 门控后中间激活）两类离群值最重的层
保留高精度激活，其余层为真 4-bit 激活；权重全程 MXFP4 不变。

- **按层数**（评审确认的判定口径）：保护 72/252 层，仍有 **180/252 = 71.4%** 的层跑真 4-bit 激活；
- **按算力**（更严格，一并披露）：这两类层占每层 matmul 的 **34.8%**，该部分计算退回 A16。

### 三、有效手段

| 手段 | 说明 |
|---|---|
| **block Hadamard 旋转** | 正交变换把激活离群值在块内摊开，是 4-bit 激活可行的前提 |
| **旋转块加大至 k=4096** | 论文取 k=128 是**在线旋转算子**的开销权衡；本任务为 fake-quant 精度评估、旋转无推理开销，故取满。论文未做此消融 |
| **全宽旋转（补 down_proj 缺口）** | 单项 **−0.0305**，详见下 |
| **GPTQ 阻尼系数 `perc_damp`** | 由默认约 0.01 提高到 0.2，单项 **−0.0261**（0.4158 → 0.4061 → 0.3982 → 0.3897） |
| 激活 scale-fitting + 联合补偿 | 前者对激活块 scale 也做附录 H 的网格重映射；后者用量化后的激活构建 Hessian，使权重补偿适配 W4A4 的真实输入 |
| 混合精度保护 | 见第二节 |

**全宽旋转**：`down_proj` 的 in_features = 12288，在 k=4096 下只能切成 3 个对角块，
是全网**唯一没有获得全宽旋转**的层，而它是最大的层（50.3M 参数 / 每层 FLOPs 的 26%）。
12288 不是 2 的幂，Sylvester 递归无法构造；`12288 = 3×4096` 亦不可行（**3 阶 Hadamard 不存在**），
故采用 `12288 = 12×1024`：Paley I 型构造 H₁₂（q=11 为素数且 ≡3 mod 4）与 Sylvester H₁₀₂₄
作 Kronecker 积——正交矩阵的 Kronecker 积仍正交，故变换合法。

**阻尼系数的机理**：最大层 `down_proj` 的 in_features = 12288，而校准样本约 1.4 万 token，
**样本/维度比仅约 1.1 : 1**（GPTQ 常用 ≥20:1），Hessian 接近奇异，
`damp = perc_damp × mean(diag(H))` 一项实际撑住了整个求逆。默认值按正常条件数选取、在此偏小；
提高阻尼可抑制由估计噪声主导的补偿方向。

该解释有一个旁证：我们也尝试过**直接加大校准集**（样本/维度比 1.1 → 5.2），
全量评测 delta 由 0.4463 变为 0.4520，**无收益**。即"补数据（治病因）无效、加阻尼（治病症）有效"。

### 四、经实测排除的手段

以下均已实测，一并汇报以说明搜索范围：

| 手段 | 结果 | 分析 |
|---|---|---|
| **激活 scale 裁剪搜索** | 变差 | 被裁掉的大激活承担 attention sink / 隐式偏置，是模型的有效部件而非噪声；**逐块 MSE 最优 ≠ 端到端 PPL 最优** |
| **加大校准集 4 倍** | +0.006 | 见第三节 |
| **权重 scale 裁剪 + 激活网格逐 token 拟合** | +0.042 | 两项打包运行，未单独归因 |
| **增加保护层（单独保护 `q_proj`）** | +0.048 | 保护 `q_proj` 而不保护 `k_proj`/`v_proj`，**拆散了功能组**：Q·Kᵀ 中两侧处于同一精度体制时量化误差可部分抵消，一侧转高精度反而引入系统性偏差。保护应按功能组整体施加 |
| **randomized Hadamard** | +0.138 | 归一化 Sylvester 首行全 1，故 (xH)[0] = √k·mean(x)，DC 分量**全部集中于坐标 0**、其余坐标纯净；随机化后 DC 摊到全部 128 个 32 元素块。**MXFP4 的 scale 是逐 32 块的，把问题集中在一个块内优于摊匀到所有块。** QuaRot / QuIP# 采用随机化，是因其工作在 per-channel / group-128 粒度，单个离群值会污染整行；block-32 下结论相反 |

### 六、请示：Qwen3.6-35B-A3B 的 W4A4 口径

35B 上有一处结构性差异，需在开展前明确口径。

该模型被识别为 `qwen3_5_moe` 混合架构，其 **256 个路由专家并非 `torch.nn.Linear`**，
而是融合存储的 3D 张量（`gate_up_proj` / `down_proj`），**约占全模型 35B 参数中的 32B**。
工具链的量化模块只作用于 `nn.Linear`，覆盖不到这部分，因此我们已为其单独实现 MXFP4 权重量化
（此前 W4A16 交付中已说明）。

问题在于：**该路径为纯权重量化，激活量化无法挂载**——融合专家的输入不经过量化模块的
`fake_quant_forward`。因此 35B 的 W4A4 只能覆盖 250 个 `nn.Linear`（attn / 线性注意力投影 /
共享专家），占大头的专家计算仍为 A16。

请明确：**35B 的「W4A4 层数占比」是否以 `nn.Linear` 为分母？**

- 若**是**（与 8B 同口径）：我们按 8B 的达标配置迁移，给出 35B 实测数据；
- 若**否**（融合专家计入分母）：该指标在当前工具链下不可达，需先为融合专家张量补齐激活量化通路，
  属工具链能力扩展，请指示是否作为独立事项处理。
