# MR-GPTQ MXFP4 低比特量化算法 —— 自验证报告

> 本报告覆盖 MR-GPTQ（Micro-Rotated GPTQ, arXiv:2509.23202）在 AMCT 上对 MXFP4 权重量化的
> 实现、测试与验收。方案见 [design.md](design.md)，逐次实验流水见 [experiment-log.md](experiment-log.md)。
> 目标数据类型 **MXFP4**（weight-only W4A16）；验收标准（任务书）：PPL 劣化 ≤ 0.4、量化层占比 ≥ 70%、显存降低 ≥ 50%。

## 1. 概述

| 项       | 值                                                                                            |
| -------- | --------------------------------------------------------------------------------------------- |
| 算法     | MR-GPTQ（GPTQ + block-wise Hadamard 微旋转 + MXFP scale fitting + 静态激活重排）              |
| 数据类型 | MXFP4（block=32，E2M1 元素 + E8M0 共享指数），weight-only                                     |
| 测试模型 | Qwen3-8B（dense）、Qwen3.6-35B-A3B（MoE）                                                     |
| 数据集   | WikiText2（test）                                                                             |
| 指标     | PPL；`delta = PPL_量化 − PPL_bf16`                                                         |
| 实现     | `src/mr_gptq_module.py`（子类化 amct `GPTQuant`，运行时注册 `mr_gptq`，零改 amct 源码） |

### 4.3 W4A4 精度评估（激活也量化 —— 按评审意见补充）—— ✅ 已达标

**结论前置**：Qwen3-8B 的 W4A4 配置**已达标**，delta = **0.3897 ≤ 0.40**，
真 4-bit 激活层占比 **71.4% ≥ 70%**。W4A4 delta 由初始实现的 0.763 降至 0.3897（**降低 49%**）。
主线 W4A16 结论不变（8B 0.273 / 35B 0.067），仍为推荐生产配置。

**动机**：weight-only（W4A16）仅得**存储**收益；matmul 时权重需反量化回 bf16，推理反而变慢。
**W4A4**（权重+激活均 4-bit）才能让 matmul 在低比特上算、拿到**计算**收益。amct 原生无 MXFP4 W4A4
组合（支持表仅 `NOT_QUANTIZE mxfp4_e2m1` weight-only），本项目在**已实现的 Hadamard 在线旋转**
基础上，于 `fake_quant_forward` 内对旋转后的激活做**逐 token、逐 32 通道块的动态 MXFP4**。

| **真 4-bit 激活层占比** | **180 / 252 = 71.4%** | ≥ 70% | ✅ |
| 权重量化层占比 | 252 / 253 = 99.6%（仅跳过 lm_head） | ≥ 70% | ✅ |
| 显存降低 | 62.3%（全模型）/ 67.4%（Linear 权重） | ≥ 50% | ✅ |

达标配置：

```bash

    --seq_len 4096 --hadamard_k 4096 --hadamard_full --perc_damp 0.2 \
    --act_protect down_proj o_proj \
```

**混合精度的口径披露**：对 `o_proj`（输入 = 注意力输出）与 `down_proj`（输入 = 门控后中间激活）
两类离群值最重的层保留高精度激活，其余层为真 4-bit 激活；**权重全程 MXFP4 不变**。

- **按层数**（评审确认的判定口径）：保护 72/252 层，仍有 **180/252 = 71.4%** 跑真 4-bit 激活；
- **按算力**（更严格，一并披露）：这两类层占每层 matmul 的 **34.8%**，该部分计算退回 A16。

#### ③ 两项关键手段的机理

**全宽旋转（`--hadamard_full`，单项 −0.0305）**

`down_proj` 的 in_features = 12288，在 `--hadamard_k 4096` 下只能切成 **3 个对角块**——
它是全网**唯一未获得全宽旋转**的层，而它是最大的层（50.3M 参数 / 每层 FLOPs 的 26%）。
而消融显示旋转块越大收益越大（k=128 → 4096 收 0.065），该缺口的代价此前被低估。

12288 不是 2 的幂，Sylvester 递归无法构造；`12288 = 3 × 4096` 亦不可行——**3 阶 Hadamard 不存在**
（Hadamard 矩阵的阶只能是 1、2 或 4 的倍数）。可行分解为 `12288 = 12 × 1024`：
Paley I 型构造 H₁₂（q = 11 为素数且 ≡ 3 mod 4）与 Sylvester H₁₀₂₄ 作 Kronecker 积——
**正交矩阵的 Kronecker 积仍正交**，故 `y = (xR)(WR)ᵀ = xRRᵀWᵀ = xWᵀ` 恒等成立。
注意 Paley 矩阵**只正交、不对称**（Sylvester 两者兼备），而旋转的正确性只需要正交。

附带观察：该层旋转的 FLOPs 增至 3 倍，**评测反而更快**（23.5 vs 27.0 s/块）——
一次大 GEMM 的硬件利用率显著高于 3 个小矩阵的批量乘。**算力账不等于时间账。**

**GPTQ 阻尼系数（`--perc_damp` 0.01 → 0.2，单项 −0.0261）**

`damp = perc_damp × mean(diag(H))`。本配置下最大层 `down_proj` 的 in_features = 12288，
而校准样本约 1.4 万 token，**样本/维度比仅约 1.1 : 1**（GPTQ 常用 ≥ 20:1），
Hessian 接近奇异，该阻尼项实际撑住了整个求逆。默认值按正常条件数选取、在此偏小。

曲线单调下降（0.4158 → 0.4061 → 0.3982 → 0.3897）指向一个明确结论：
**补偿方向中有相当比例由估计噪声主导，压制它们比使用它们更划算**——正是 1.1:1 所预言的。
这也解释了 ④ 中"直接加大校准集无收益"这一负结果：**治病因（补数据）无效、治病症（加阻尼）有效。**

#### ④ 经实测排除的手段（负结果）

以下均为全量 73 块实测（`act_clip` 为 20 块），一并记录以说明搜索范围与边界：

| 手段 | 结果 | 分析 | 日志 |
|------|------|------|------|
| **激活 scale 裁剪搜索**（逐块搜 α 最小化量化 MSE，候选含 1.0） | 变差 | 被裁掉的大激活承担 attention sink / 隐式偏置，是模型的有效部件而非噪声；**逐块 MSE 最优 ≠ 端到端 PPL 最优** | — |
| **加大校准集 4 倍**（样本/维度比 1.1 → 5.2） | 0.4520（+0.006） | 见 ③ 阻尼一节 | `w4a4_best_73.log` |
| **权重 scale 裁剪 + 激活网格逐 token 拟合** | 0.4884（+0.042） | 两项打包运行，未单独归因 | `w4a4_wclip_rowfit_73.log` |
| **增加保护层**（`layers.0` 的 gate/up/q_proj） | 0.4636（+0.048） | 保护 `q_proj` 而未保护 `k_proj`/`v_proj`，**拆散了功能组**：Q·Kᵀ 中两侧处于同一精度体制时量化误差可部分抵消，一侧转高精度反而引入系统性偏差。**量化误差在网络中相互抵消，"移除一个误差源"并非局部可加操作**，保护须按功能组整体施加 | `w4a4_prot3_73.log` |
| **randomized Hadamard**（旋转前乘随机 ±1 对角阵） | 0.5542（+0.138） | 归一化 Sylvester 首行全 1，故 (xH)[0] = √k·mean(x)，而 RMSNorm 不居中——DC 分量**全部集中于坐标 0**，其余坐标纯净；随机化后 DC 摊到全部 128 个 32 元素块。**MXFP4 的 scale 是逐 32 块的，把问题集中在一个块内优于摊匀到所有块。** QuaRot / QuIP# 采用随机化，是因其工作在 per-channel / group-128 粒度，单个离群值会污染整行；block-32 下结论相反 | `w4a4_randhad_73.log` |

**该节的价值**：负结果确定了本配置下的搜索边界，且其中两条给出了**与量化粒度相关的一般性结论**
（大激活不可裁剪；跨工作迁移做法前须核对量化粒度）。

#### ⑤ 可复现性与测量方法说明

**可复现性**：在代码经过六个提交的重构（Hessian 分块累积、校准跳过 lm_head、关闭 KV cache 等）
之后，重跑此前记录的最优配置得 PPL **9.435639**，与记录值 9.4356 **逐位吻合**
（`w4a4_repro_73.log`）。这同时验证了整条管线的确定性可复现，以及上述三项工程重构对数值的中性。

**测量方法的自我修正**：早期为节省时间曾用测试集**前 20 块**做快速筛选。
后经两组同配置的 20/73 对照发现，其偏移在 **−0.011 与 +0.042 之间摆动（摆幅 0.053）**，
大于多数待测增量——即该子集不仅有偏，**偏差还随配置变化，故连排序都不可靠**。
**本节所有定量结论均基于全量 73 块**；20 块数据仅用于早期筛选，不作定量依据（见 §5 说明）。

#### ⑥ 与已发表结果的量级参照（⚠️ 非对等对比）

用相同评测设置（WikiText2，seq_len=2048，全量 146 块）重测早期配置，作量级参照。

> **⚠️ 请勿读作"算法优劣排名"。** 本工作与表中方法的**量化配置不对等**，且差异全部对本工作有利。
> 此表仅用于确认本实现的精度处于合理量级。

| 方法（W4A4，Qwen3-8B） | PPL | delta |
|------|-----|-------|
| W16A16 基线 | 9.7（文献）/ **9.7154（本项目实测）** | — |
| 本工作（早期配置，seq_len=2048） | 10.2594 | 0.544 |
| MosaicQuant（arXiv:2606.15652 Table 1） | 11.2 | 1.5 |
| SpinQuant | 11.4 | 1.7 |
| QuaRot | 15.6 | 5.9 |
| RTN / SmoothQuant | 4392 / 3360.1 | 崩溃 |

**配置不对等的三点差异**：① **权重量化粒度差 128×**（对方 per-channel INT4 = 整行 4096 元素共 1 个
scale，本工作 MXFP4 block-32 = 每行 128 个 scale，属**格式代差**而非算法优劣）；② 激活粒度差 4×；
③ 本工作使用层级混合精度（按 FLOPs 计 34.8% 退回 A16），对方为全量 W4A4。

**结论**：本表不足以支撑"优于 SOTA"的判断，仅说明在 MXFP4 block-32 + 混合精度这一配置下，
本实现的 W4A4 精度处于合理量级、未出现同表 RTN/SmoothQuant 那类崩溃。

- 说明：本节为 **fake-quant 精度评估**；真实 W4A4 部署需低比特激活算子（Ascend C），
  属推理加速课题，不在本量化算法任务范围。

## 5. 消融实验（算法有效性验证，Qwen3-8B，seq_len=2048）

逐个开启增量，验证每一步的贡献：

| 方案                            | PPL     | delta  | 说明                                 |
| ------------------------------- | ------- | ------ | ------------------------------------ |
| GPTQ-mxfp4（无增量）            | 10.1332 | +0.418 | 纯 MXFP4 粗糙，**不达标**      |
| + Hadamard(k=128)               | 10.0747 | +0.359 | 微旋转正态化权重，**越过门槛** |
| + scale fitting（完整 MR-GPTQ） | 10.0499 | +0.335 | E8M0 网格重映射，进一步降            |

**结论**：各增量逐步生效；Hadamard 是 MXFP4 头号杠杆（纯 GPTQ 不达标，微旋转后达标）。
外部交叉验证：我们的 GPTQ-mxfp4（10.1332）与 amct 自带 GPTQ（10.1369）逐位吻合，实现正确。

**关于论文的第三项增量（静态激活重排）**：本实现**有意未采用**。该增量按幅度重排通道、
使同量级的通道共享一个 32 块；而本实现已对每层施加**全宽** Hadamard 旋转（§4.3 ③），
旋转后各通道近似可交换，按幅度分组已无物可分——与 SmoothQuant 式难度迁移被旋转吸收同理。
（GPTQ 自带的 act-order，即按 Hessian 对角降序处理列，本实现始终启用，与此为两回事。）

- 消融各次运行 `Score:` 见日志：`src/logs/mrgptq_had128_8b.log`（+Hadamard）、
  `mrgptq_had_sf_8b.log`（+scale fitting）、`mrgptq_v1_8b.log`（无增量 baseline）等。
- **评测口径说明**：本节各行均为**全量**评测（seq_len=2048，146 块）。项目早期曾以测试集
  前 20 块做快速筛选，后经两组同配置的 20/73 对照发现其偏移在 −0.011 与 +0.042 之间摆动
  （摆幅 0.053）——该子集不仅有偏，**偏差还随配置变化**。故本报告所有定量结论均基于全量评测，
  20 块数据仅用于早期方向筛选、不作定量依据（详见 §4.3 ⑤）。

- **W4A4 的开销来源**：weight-only 下旋转与量化只在校准期做一次，评测期是普通 `F.linear`；
  W4A4 则**每次前向都要**对激活做旋转 + 动态 MXFP4（scale 逐 token 逐块实时计算），
  故评测耗时显著高于 W4A16。这属 fake-quant 精度评估的固有开销——真实部署由低比特激活算子
  承担，不构成推理性能结论。
- 附带观察：`down_proj` 改为全宽旋转后，该层旋转 FLOPs 增至 3 倍，**单块评测耗时反而下降**
  （27.0 → 23.5 s/块）——一次大 GEMM 的硬件利用率高于 3 个小矩阵的批量乘。

## 7. 结论

- Qwen3-8B（dense）：MXFP4 weight-only 下 MR-GPTQ 三项硬指标（delta 0.273 / 覆盖 99.6% / 显存 67.4%）全部达标 ✅。
- Qwen3.6-35B-A3B（qwen3_5_moe 混合 MoE）：delta 0.067 / nn.Linear 覆盖 71.4% / 全参数 97.0% / 显存 71.2%，全部达标 ✅。
  额外解决 amct 覆盖不到融合路由专家（占 32B）的问题，自实现融合专家 MXFP4 量化。
- 算法实现自包含、零改 amct 源码、运行时注册，消融链证明各增量有效。
- **W4A4（按评审意见补充）：Qwen3-8B 已达标 ✅**——delta **0.3897 ≤ 0.40**、真 4-bit 激活层
  **71.4% ≥ 70%**（按层数口径）、权重量化层 99.6%、显存降低 62.3%。W4A4 delta 由初始实现的
  **0.763 降至 0.3897（降低 49%）**。关键为两项此前未覆盖的改动：全宽旋转（补 `down_proj`
  的 12288 维旋转缺口，−0.0305）与 GPTQ 阻尼系数调优（−0.0261）。详见 §4.3。
- 报告同时记录 **5 项经实测排除的手段**（§4.3 ④），其中两条给出与量化粒度相关的一般性结论：
  大激活承担 attention sink 故不可裁剪；randomized Hadamard 在 block-32 粒度下有害
  （集中优于摊匀），与其在 per-channel 粒度下的效果相反。
- **可复现性已实测验证**：代码经六个提交重构后重跑最优配置，PPL 与记录值逐位吻合（§4.3 ⑤）。
